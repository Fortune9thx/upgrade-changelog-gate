# Changelog

## 1.3.0

- A GenLayer Portal steward requested changes before continuing review: *"a proposal's stake can remain locked forever if evaluation never reaches validator agreement. Please add a bounded cancellation or expiry path for still-pending proposals that returns the recorded stake exactly once, cannot run after evaluation, and cannot bypass a resolved forfeiture."* This directly overturned this account's own third-benchmark-pass conclusion that no such escape hatch was needed -- that conclusion conflated "permissionlessly retriable" with "guaranteed to eventually converge," which are not the same claim. Full disclosure of the reasoning error: `docs/DESIGN.md`'s "Steward review" section.
- **Added `reclaim_expired_proposal(proposal_id: str) -> None`.** Permissionlessly callable by anyone once a still-`"pending"` proposal has sat unevaluated for at least `PROPOSAL_EVALUATION_TIMEOUT_SECONDS` (72h). Refunds the proposer's recorded stake and marks the proposal `"expired"` -- a third terminal status distinct from `"evaluated"`. Shares the exact `status == "pending"` precondition `evaluate_proposal` itself requires, and both methods flip status away from `"pending"` before any GEN transfer, which is what guarantees the stake is ever released exactly once, that the method cannot run after evaluation, and that it can never bypass an already-resolved forfeiture.
- New `proposal["expired_at"]` field (`None` until expiry) and a new `ProposalExpired` event, matching this contract's existing event-emission convention.
- Uses `datetime.now(timezone.utc)` (not `gl.message_raw.get("datetime")`) for the elapsed-time comparison specifically -- explicitly sanctioned as deterministic by `genvm-lint`'s own source (`W002`'s forbidden-call list excludes it by name), and the only mechanism `gltest`'s direct-mode mock can actually fast-forward for testing. Every other timestamp in the contract is unchanged.
- 58 direct-mode tests (up from 50) -- `TestExpiryReclaim`'s 8 new tests reproduce the steward's three requirements directly, not just the happy path: reclaiming before timeout fails; reclaiming after timeout succeeds (including the zero-stake case); an evaluated proposal can never be reclaimed; an expired proposal can never be evaluated; a second reclaim attempt fails; the call is genuinely permissionless; an unknown proposal is rejected. `genvm-lint check`/`typecheck` both clean.

Deploy tx `0xe173c8db06fb40a74828a46c455996585a7ed4885e5360ab92f8842842ab9bc1`: `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`, confirmed readable (`get_proposal_count` returns `0`). ## 1.1.0

- Strict post-build security audit found and closed two real gaps:
  - **Stale-proposal clobber bug.** `accept_proposal` applied `proposal["new_content"]` unconditionally, with no check that the protocol was still at the version the proposal's diff was computed against. With permissionless, open proposing, two proposals could exist against the same baseline before either was accepted; accepting the second afterward would silently overwrite the protocol's content with a diff computed from the now-stale first baseline, discarding whatever the first upgrade changed for any field the second proposal didn't also touch. A real "lost update" bug, not a hypothetical one. Fixed: every proposal now stores `based_on_version` at `propose_upgrade` time; `accept_proposal` rejects outright if the protocol has since moved to a different version, with an explicit message telling the proposer to submit a fresh proposal instead.
  - **Case-sensitive verdict matching.** `_coerce_verdict` required an exact-case match against `"FAITHFUL"`/`"INCOMPLETE"`/`"MISLEADING"` -- a model writing `"Faithful"` instead, a casing inconsistency rather than dishonesty, failed closed to `INCOMPLETE` unnecessarily. Fixed with case-insensitive matching (`.strip().upper()`); the canonical uppercase string is always what gets stored/returned regardless of the model's casing, and the fail-closed direction for genuinely invalid output is unchanged.
- 50 direct-mode tests (up from 43) -- `TestStaleProposalGuard` reproduces the exact two-competing-proposals scenario and proves the clobber is rejected, not just that ordinary acceptance still works; new case-insensitivity tests in `TestVerdictCoercion` prove the fix without widening the fail-closed net for genuine garbage. `genvm-lint check` and `genvm-lint typecheck` both clean.
- Redeployed to `0xfd702c49bbDaD2BD47438719d85F06cAD44983Cf` on GenLayer Bradbury. Deploy tx `0x651d80f7619235eab4b93be9b65d45b6c43508981a586e6400c7ec6093ad557a`: `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`, confirmed readable. Supersedes the 1.0.0 deployment at `0x60553Fb5BAE7E4681a330169e2c17E8dde414f97` -- both fixes changed only deterministic code, so 1.0.0's live consensus-mechanism proof (`docs/DESIGN.md`'s "Live verification" section) still stands for this redeployment; the new guards are proven instead by the regression tests above.

## 1.0.0

- Initial `register_protocol` / `propose_upgrade` / `evaluate_proposal` / `accept_proposal` / `update_stake_requirement` lifecycle: a protocol registers versioned JSON content; anyone may permissionlessly propose an upgrade backed by a GEN stake; the contract computes a deterministic field-by-field diff between old and new content; `gl.vm.run_nondet_unsafe`-based leader/validator consensus (a hand-written independent-re-derivation validator, not a convenience wrapper) judges whether the proposer's changelog faithfully accounts for that diff, forced into one of three discrete buckets (`FAITHFUL`/`INCOMPLETE`/`MISLEADING`).
- Stake routing: a `MISLEADING` verdict forfeits the proposer's stake to the protocol owner; `FAITHFUL` or `INCOMPLETE` refunds it. Only a `FAITHFUL` verdict lets the protocol owner apply the upgrade via `accept_proposal`, separating "is this changelog honest" (GenLayer's job) from "do we want this change" (the owner's own call).
- Storage: `protocols`/`proposals`/`protocol_latest_proposal` as `TreeMap[str, str]` (JSON-encoded records), `proposal_counter` as `u256` -- the Bradbury-verified reliable storage pattern.
- Every design lesson from this account's prior GenLayer primitives applied proactively rather than discovered after the fact: `protocol_id` is format-restricted to ASCII from the start (closing the Unicode-encoding-collision class of bug before it could occur, not after); the changelog gets the same non-blocking manipulation-heuristic screen as this account's other caller-controlled-instruction-adjacent fields; the verdict vocabulary is a fixed three-string enum with no numeric clamp arithmetic at all (closing the whole class of non-finite-float edge case a numeric bucket scale would need explicit guards against); `.github/workflows/ci.yml` (lint, typecheck, full test suite on every push/PR) shipped from the first commit, not added in a later audit pass.
- 43 direct-mode tests, including a dedicated adversarial scenario (an honest fee-change changelog; a changelog that silently omits an undisclosed admin-address change, correctly judged `INCOMPLETE`; and a changelog with an active false claim about that field, correctly judged `MISLEADING`) and dedicated validator-independence tests (`TestValidatorIndependence`) proving `validator_fn` genuinely re-derives its own verdict via `direct_vm.run_validator()` and rejects a mismatched leader claim while ignoring reason-text differences. `genvm-lint check` and `genvm-lint typecheck` both clean.
- Deployed to `0x60553Fb5BAE7E4681a330169e2c17E8dde414f97` on GenLayer Bradbury. Deploy tx `0x2cd73a50a9b3cdc33db642487ca68d5a6020d018c6cd19abe4b4b850e2c6b4f8`: `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`, confirmed readable.
- **Full live transaction sequence run end to end, not just a bare deploy:** `register_protocol` (tx `0xde235b869c6f3852238d6265c610efc170b92a534622f5af4a3dfaced39c74c1`) → `propose_upgrade` with a deliberately adversarial changelog (tx `0x326d9da525e9acd4c461d900edafb790161b3239e1cdae962329a76ab7c51400`) → `evaluate_proposal` (tx `0x36a0f4d362dcb95efebd7c56b279d6fc8ca4d5980640e8ab28a27ac8d574c761`), all `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`.
