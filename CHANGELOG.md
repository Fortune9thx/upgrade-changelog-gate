# Changelog

## 1.0.0

- Initial `register_protocol` / `propose_upgrade` / `evaluate_proposal` / `accept_proposal` / `update_stake_requirement` lifecycle: a protocol registers versioned JSON content; anyone may permissionlessly propose an upgrade backed by a GEN stake; the contract computes a deterministic field-by-field diff between old and new content; `gl.vm.run_nondet_unsafe`-based leader/validator consensus (a hand-written independent-re-derivation validator, not a convenience wrapper) judges whether the proposer's changelog faithfully accounts for that diff, forced into one of three discrete buckets (`FAITHFUL`/`INCOMPLETE`/`MISLEADING`).
- Stake routing: a `MISLEADING` verdict forfeits the proposer's stake to the protocol owner; `FAITHFUL` or `INCOMPLETE` refunds it. Only a `FAITHFUL` verdict lets the protocol owner apply the upgrade via `accept_proposal`, separating "is this changelog honest" (GenLayer's job) from "do we want this change" (the owner's own call).
- Storage: `protocols`/`proposals`/`protocol_latest_proposal` as `TreeMap[str, str]` (JSON-encoded records), `proposal_counter` as `u256` -- the Bradbury-verified reliable storage pattern.
- Every design lesson from this account's prior GenLayer primitives applied proactively rather than discovered after the fact: `protocol_id` is format-restricted to ASCII from the start (closing the Unicode-encoding-collision class of bug before it could occur, not after); the changelog gets the same non-blocking manipulation-heuristic screen as this account's other caller-controlled-instruction-adjacent fields; the verdict vocabulary is a fixed three-string enum with no numeric clamp arithmetic at all (closing the whole class of non-finite-float edge case a numeric bucket scale would need explicit guards against); `.github/workflows/ci.yml` (lint, typecheck, full test suite on every push/PR) shipped from the first commit, not added in a later audit pass.
- 43 direct-mode tests, including a dedicated adversarial scenario (an honest fee-change changelog; a changelog that silently omits an undisclosed admin-address change, correctly judged `INCOMPLETE`; and a changelog with an active false claim about that field, correctly judged `MISLEADING`) and dedicated validator-independence tests (`TestValidatorIndependence`) proving `validator_fn` genuinely re-derives its own verdict via `direct_vm.run_validator()` and rejects a mismatched leader claim while ignoring reason-text differences. `genvm-lint check` and `genvm-lint typecheck` both clean.
- Deployed to `0x60553Fb5BAE7E4681a330169e2c17E8dde414f97` on GenLayer Bradbury. Deploy tx `0x2cd73a50a9b3cdc33db642487ca68d5a6020d018c6cd19abe4b4b850e2c6b4f8`: `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`, confirmed readable.
- **Full live transaction sequence run end to end, not just a bare deploy:** `register_protocol` (tx `0xde235b869c6f3852238d6265c610efc170b92a534622f5af4a3dfaced39c74c1`) → `propose_upgrade` with a deliberately adversarial changelog (tx `0x326d9da525e9acd4c461d900edafb790161b3239e1cdae962329a76ab7c51400`) → `evaluate_proposal` (tx `0x36a0f4d362dcb95efebd7c56b279d6fc8ca4d5980640e8ab28a27ac8d574c761`), all `ACCEPTED`/`AGREE`/`FINISHED_WITH_RETURN`. The real, unscripted model call correctly classified a silently-omitted admin-key change as `INCOMPLETE`, citing the exact undisclosed field -- a real finding that corrected an imprecise assumption in the original test narrative (which had expected `MISLEADING` for pure omission; the contract's own bucket definitions say that's actually the correct call, since `MISLEADING` requires an active contradiction, not just a gap). Test suite updated to match this verified behavior, plus a new test for the sharper "active false claim" case that does fit `MISLEADING`. Full record in `docs/DESIGN.md`'s "Live verification" section.
